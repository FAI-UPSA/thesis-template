Kit de inicio para elaborar trabajos de grado de la Universidad Privada de Santa Cruz de la Sierra (UPSA) mediante https://typst.app/[Typst]. Incluye documentos de ejemplo, recursos, tareas de compilación y una plantilla reutilizable para mantener la consistencia de la presentación académica.

Los documentos incluidos son ejemplos que podés adaptar a los requisitos de tu carrera y a las indicaciones de tu asesor.

== Primeros pasos

=== Requisitos

* https://typst.app/open-source/[Typst]: compilador para generar los documentos PDF.
* https://git-scm.com/[Git]: necesario para clonar el repositorio y obtener sus submódulos mediante los comandos indicados.
* https://code.visualstudio.com/[Visual Studio Code]: editor recomendado, aunque no obligatorio.
* https://marketplace.visualstudio.com/items?itemName=myriad-dreamin.tinymist[Tinymist]: extensión recomendada para VS Code, con herramientas de edición, diagnósticos y vista previa de Typst.
* https://taskfile.dev/[Task]: herramienta opcional para ejecutar las tareas de compilación incluidas.

No es necesario contratar una suscripción de Typst para trabajar localmente con este kit.

=== Obtener el proyecto

La forma recomendada de obtener todos los archivos es clonar el repositorio junto con sus submódulos:

[source,shell]
....
git clone --recurse-submodules <nombre del repositorio copiado>
....

Si ya clonaste el repositorio sin los submódulos, ejecutá desde su directorio:

[source,shell]
----
git submodule update --init --recursive
----

Si descargás el repositorio como ZIP, tené en cuenta que GitHub no incorpora automáticamente los archivos de los submódulos. Deberás obtener el contenido de `template` por separado.

=== Preparar el entorno

. Abrí la carpeta del proyecto en VS Code.
. Instalá la extensión Tinymist.
. Comprobá que Typst esté disponible desde la terminal.
. Verificá que el submódulo `template` contenga los archivos de la plantilla.
. Comprobá la disponibilidad de las fuentes necesarias en `assets/fonts`.
. Abrí el documento de ejemplo que quieras utilizar y reemplazá sus datos.

La configuración de parámetros, funciones y estilos se explica en el https://github.com/FAI-UPSA/thesis-template[README de la plantilla]. Este archivo se concentra en el uso del kit de inicio.

=== Compilación directa

Podés compilar los documentos con Typst, sin instalar Task.

Por ejemplo, para generar el plan de trabajo desde la raíz del repositorio:

[source,shell]
----
typst compile --root . --font-path assets/fonts documents/proposal/proposal.typ
----

El comando utiliza la raíz del proyecto para resolver los archivos y agrega `assets/fonts` como directorio de búsqueda de fuentes.

Si necesitás comprobar que el resultado no dependa de las fuentes instaladas en tu sistema, podés utilizar `--ignore-system-fonts`. Esta opción no elimina las fuentes integradas que Typst proporciona como respaldo.

=== Compilación mediante Task

Si instalaste Task, podés generar los documentos con sus tareas correspondientes:

[source,shell]
----
task thesis
task proposal
task study
----

Consultá `Taskfile.yaml` para conocer los comandos, argumentos y destinos de salida.

Las tareas que no indican un destino explícito generan el PDF junto al archivo fuente.

=== Exportar la entrega BIME como Bundle

Desde la raíz del Starter Kit, ejecutá `task bime`. La tarea habilita la función experimental `bundle` de la CLI de Typst y usa `documents/bime/book.typ` para reunir el informe, el resumen BIME, la cubierta, el lomo y los registros BibLaTeX y Hayagriva. Los archivos generados quedan en `documents/bime/book/`.

La inicialización predeterminada de la plantilla en Typst Universe contiene el informe y su bibliografía. Para generar la entrega agrupada, usá el archivo `book.typ` y la tarea incluidos en el Starter Kit.

== Recursos y estructura

* `assets/fonts`: fuentes tipográficas utilizadas por los documentos y sus avisos de licencia.
* `assets/images`: imágenes, logotipos y otros recursos gráficos.
* `data`: datos utilizados por los documentos de ejemplo.
* `documents`: archivos principales de los distintos documentos académicos.
* `template`: submódulo que contiene la plantilla reutilizable y su documentación.
* `.vscode`: configuración y recomendaciones para VS Code.
* `.github/workflows`: tareas de automatización mediante GitHub Actions.

IMPORTANT: Las fuentes necesarias deben estar disponibles en el entorno de compilación. Su presencia en otro equipo no garantiza que también estén disponibles en Linux, macOS o el editor web de Typst. Tampoco debe suponerse que cualquier fuente instalada pueda redistribuirse legalmente con el repositorio.

== Uso en el editor web de Typst

El https://typst.app/[editor web de Typst] permite trabajar con proyectos desde el navegador.

Para utilizar este kit, incorporá los archivos del proyecto, las fuentes necesarias y el contenido del submódulo `template`, conservando las rutas utilizadas por los documentos.

Las tareas de Task y GitHub Actions no se ejecutan dentro del editor web. También será necesario comprobar que las importaciones y dependencias funcionen correctamente en ese entorno.

== Estado de la plantilla y los ejemplos

Los documentos incluidos son ejemplos de uso. Sus configuraciones deben comprobarse frente a los requisitos vigentes de la carrera y las indicaciones del asesor.

=== Tipografía

Alegreya es el conjunto predeterminado de la plantilla. Las fuentes de los ejemplos están en `assets/fonts`, y las tareas ya apuntan a esa carpeta. Si compilás directamente, pasá esa ruta con `--font-path assets/fonts`. Podés cambiar el conjunto de un documento con `typeface`.

=== Capítulos y partes

La organización por partes del ejemplo original responde a las particularidades de un proyecto desarrollado mediante la metodología ICONIX. No representa una estructura obligatoria para otros trabajos.

Los capítulos son la estructura predeterminada. Para agruparlos en partes, activá `multi-part: true` en la configuración del documento y agregá `#part[Título]` donde corresponda.

La jerarquía de encabezados debe ser semánticamente correcta en ambas modalidades. Si aparecen errores durante las comprobaciones de accesibilidad, es necesario corregir la estructura del documento y no simplemente desactivar las comprobaciones.

== Guardado y revisión académica

Los asesores y docentes guía pueden revisar los PDF generados sin instalar Typst ni utilizar Git.

Para una revisión sencilla:

. Generá un PDF del estado actual del documento.
. Compartilo mediante OneDrive o Google Drive.
. Recibí las observaciones del asesor.
. Aplicá las correcciones en los archivos fuente.
. Generá una nueva versión identificable para la siguiente revisión.

Es conveniente conservar las versiones enviadas a revisión sin sobrescribir los PDF que ya contienen observaciones.

Las funciones de comentarios y anotación dependen del visor utilizado. Algunos comentarios se almacenan en la plataforma y no necesariamente quedan incorporados al archivo PDF descargado.

Git es opcional para la redacción, pero resulta útil para registrar cambios, recuperar versiones y asociar entregas a estados determinados del proyecto.

Si utilizás carpetas sincronizadas con OneDrive o Google Drive, evitá modificar simultáneamente el mismo archivo fuente desde varios equipos.

== Compilación en GitHub Actions

El repositorio incluye un flujo de automatización que compila los documentos y permite descargar el contenido de `out` como artefacto desde la ejecución de GitHub Actions.

Si incorporás nuevos documentos o modificás sus destinos de salida, comprobá que los archivos generados queden incluidos en el artefacto descargable.

No publiques repositorios, documentos o artefactos que contengan información confidencial sin revisar previamente sus permisos de acceso.

== Dudas y problemas

Podés utilizar _Issues_ para informar errores del kit y _Discussions_, cuando esté habilitado, para consultas generales.

Al informar un problema, procurá incluir:

* El documento y comando utilizados.
* La versión de Typst.
* El mensaje de error.
* Los pasos necesarios para reproducir el problema.

Evitá publicar datos personales, información confidencial de investigaciones o contenido reservado de trabajos académicos.
